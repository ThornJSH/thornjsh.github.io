## 1. 시스템 한눈에 보기

### 1-1. 구성 요소

| 구성 요소 | 역할 |
|---|---|
| **텔레그램 봇 "도연"** (`@thorn_schedule_bot`) | 사용자와 대화하는 창구 |
| **Cloudflare Worker** (`dobiseo-relay`) | 텔레그램 메시지를 받자마자 응답하고, Apps Script로 넘겨주는 중계 서버 |
| **Google Apps Script** (`Thorn_Schedule`) | 봇의 두뇌. 메시지 해석, 일정 등록·수정, 브리핑, 알림 처리 |
| **Gemini API** | 자연어 해석(일정·할 일 추출, 수정 대상 찾기, 빈 시간 요청 해석). 링크는 보내지 않음 |
| **구글 캘린더** | 일정이 실제로 저장되는 곳 |
| **구글 스프레드시트** | 일정 목록(`일정목록`), 할 일(`할일목록`), 검토 목록(`검토목록`), 동기화 기록(`_동기화기록`) 보관 |

### 1-2. 메시지 흐름

```
[사용자] ──메시지──▶ [텔레그램]
                        │ (웹훅)
                        ▼
              [Cloudflare Worker: dobiseo-relay]
               · 텔레그램에는 즉시 "ok" 응답
               · 비밀키를 붙여 Apps Script로 전달
                        │
                        ▼
              [Apps Script 웹앱 doPost]
               · 명령어·빠른 조회·검토 목록(링크) → 즉시 답장 (Gemini 미사용)
               · 그 외 → 보관함(INBOX)에 저장 후 순서대로 처리
                        │
            ┌───────────┼────────────┐
            ▼           ▼            ▼
        [Gemini]   [구글 캘린더]  [스프레드시트]
                        │
                        ▼
              [텔레그램으로 답장]

[1분 트리거 pollUpdates] → 아침·저녁 브리핑, 일정 알림, 저녁 완료 확인, 혼잡 재시도
                          (시각은 /setup 설정값 — 기본 07시·17시·1시간 전·19시)
```

### 1-3. 두 가지 응답 방식

| 방식 | 설명 | 현재 |
|---|---|---|
| **중계(웹훅) 방식** | Cloudflare Worker를 거쳐 메시지가 즉시 도착 (응답 몇 초) | ✅ 사용 중 |
| **폴링 방식 (예비)** | 1분마다 텔레그램에서 메시지를 가져옴 (응답 최대 1분 지연) | 중계 문제 시 `stopRelay()`로 전환 |

> 어느 방식이든 **1분 트리거(`pollUpdates`)는 항상 켜 두어야** 합니다. 브리핑·알림·완료 확인·혼잡 재시도를 담당합니다.

## 3. 텔레그램 봇 만들기 (BotFather)

> 이미 봇(`@thorn_schedule_bot`)이 있다면 **3-3 명령어 메뉴 등록**만 하면 됩니다.

### 3-1. 봇 생성
1. 텔레그램에서 **@BotFather** 검색 → 대화 시작
2. `/newbot` 입력
3. 봇 표시 이름 입력 (예: `도연`)
4. 봇 사용자명 입력 — 반드시 `bot`으로 끝나야 함 (예: `thorn_schedule_bot`)
5. 발급된 **봇 토큰**(`123456789:AA...` 형태)을 안전한 곳에 보관
   - 이 토큰은 Apps Script의 스크립트 속성 `TG_TOKEN`에 넣습니다. (6-5 참고)
   - ⚠️ 토큰이 노출되면 BotFather에서 `/revoke`로 재발급하세요.

### 3-2. (선택) 봇 프로필 꾸미기
- `/setdescription` : 봇 소개 문구
- `/setuserpic` : 프로필 사진

### 3-3. 명령어 메뉴 등록 (권장)
BotFather에서 `/setcommands` → 봇 선택 → 아래 내용을 그대로 붙여 넣기:

```
start - 시작 및 사용법
today - 오늘 일정 브리핑
week - 앞으로 1주일 일정
todo - 할 일 목록
review - 검토 목록
setup - 브리핑·알림 시각 설정
check - 오늘 일정 완료 확인
pending - 처리하지 않은 지난 일정
briefon - 아침·저녁 브리핑 켜기
briefoff - 브리핑 끄기
remindon - 일정 알림 켜기
remindoff - 일정 알림 끄기
checkon - 저녁 완료 확인 켜기
checkoff - 저녁 완료 확인 끄기
```

이제 채팅창에서 `/`를 입력하면 명령어 목록이 나타납니다.
> 명령어가 추가되면(예: `/review`, `/setup`) 이 목록을 **다시 붙여 넣어야** 메뉴에 보입니다. 명령어 자체는 메뉴 등록과 상관없이 동작합니다.

## 4. Gemini API 키 발급

1. https://aistudio.google.com 접속 → Google 계정 로그인
2. **Get API key** → **Create API key**
3. 발급된 키를 Apps Script 스크립트 속성 `GEMINI_API_KEY`에 저장 (6-5 참고)

### 사용 모델

| 용도 | 기본 모델 | 바꾸는 방법 |
|---|---|---|
| 도연 (일정 해석) | `gemini-3.8-flash` | 스크립트 속성 `GEMINI_MODEL` |
| 혼잡 시 보조 모델 | `gemini-3.5-flash-lite` | `GEMINI_FALLBACK_MODEL` (`none`이면 사용 안 함) |
| 도비서 (기본 꺼짐) | `gemini-3.8-flash` | `AGENT_MODEL` |

> 💡 비용을 줄이려면 `GEMINI_MODEL`을 `gemini-3.5-flash-lite`로 바꿀 수 있습니다. 명령어·빠른 조회·검토 목록·브리핑은 Gemini를 쓰지 않으므로 비용과 무관합니다.
> ⚠️ Google이 이전 세대 모델을 "새 사용자에게 제공 중단"하는 경우가 있습니다. `404 … no longer available` 오류가 나면 모델명을 최신 버전으로 바꾸세요.

## 5. 구글 캘린더·스프레드시트 준비

### 5-1. 캘린더
- 일정이 등록될 캘린더 ID는 `Code.gs` 상단의 `CALENDAR_ID` 상수에 지정되어 있습니다.
- 캘린더 ID 확인: 구글 캘린더 → 해당 캘린더 **설정 및 공유** → **캘린더 통합** → **캘린더 ID**
- Apps Script를 실행하는 계정에 그 캘린더의 **"변경 및 공유 관리"** 권한이 있어야 합니다.

### 5-2. 스프레드시트
- 일정·할 일을 기록할 스프레드시트를 준비하고 **스프레드시트 ID**를 확인합니다.
  - 주소 `https://docs.google.com/spreadsheets/d/【여기가 ID】/edit`
- 현재 Apps Script는 **독립형 프로젝트**이므로 스크립트 속성 `SPREADSHEET_ID`가 필수입니다.
- 탭은 처음 쓸 때 자동으로 만들어집니다: `일정목록`, `할일목록`, `검토목록`, `_동기화기록`(숨김)
- 일정 탭 이름은 **`일정목록`으로 맞추는 것을 권장**합니다. 이 이름이 없으면 봇이 '첫 번째 탭'을 일정 탭으로 쓰기 때문에, 탭 순서가 바뀌면 다른 탭을 일정 탭으로 착각할 수 있습니다.

## 6. Google Apps Script(GAS) 설정

### 6-1. clasp 설치 (최초 1회)
명령 프롬프트(cmd)에서:
```
npm install -g @google/clasp
clasp --version
```

### 6-2. Apps Script API 켜기 (최초 1회)
1. https://script.google.com/home/usersettings 접속
2. **Google Apps Script API**를 **사용**으로 변경

### 6-3. clasp 로그인 (최초 1회)
```
clasp login
```
브라우저가 열리면 **운영 Google 계정**으로 로그인하고 권한을 허용합니다.

### 6-4. 프로젝트 연결 확인
`E:\GAS\TeleBot\.clasp.json`:
```json
{
  "scriptId": "17TZeT-3_1WOTnfjpeNvhq5hQXG6Egu-dfwOWjbvsSbf9rvi9bUEgJMnr",
  "rootDir": "",
  "scriptExtensions": [".gs"]
}
```
`.claspignore` (Apps Script로 올리지 않을 파일):
```
.git/**
node_modules/**
README.md
env.txt
*.txt
*.md
worker.js
Claude outputs/**
```
> ⚠️ `rootDir`이 폴더 전체(`""`)이므로 **하위 폴더의 `.gs` 파일도 함께 올라갑니다.** 다른 프로젝트용 코드(예: `Claude outputs\회사일정_보내기.gs`)가 섞이면 이름 충돌로 봇 전체가 멈출 수 있으니, TeleBot 폴더에는 TeleBot용 `.gs`만 두거나 `.claspignore`에 추가하세요.
> `clasp push` 결과에 **`appsscript.json`, `Code.gs` 두 개만** 나오면 정상입니다. (`clasp status`의 Tracked files로도 확인)

`appsscript.json` 핵심 설정:
```json
{
  "timeZone": "Asia/Seoul",
  "runtimeVersion": "V8",
  "webapp": { "executeAs": "USER_DEPLOYING", "access": "ANYONE_ANONYMOUS" },
  "oauthScopes": [
    "https://www.googleapis.com/auth/script.external_request",
    "https://www.googleapis.com/auth/calendar",
    "https://www.googleapis.com/auth/spreadsheets",
    "https://www.googleapis.com/auth/script.scriptapp"
  ]
}
```

### 6-5. 스크립트 속성 등록
Apps Script 편집기 → 왼쪽 ⚙️ **프로젝트 설정** → 맨 아래 **스크립트 속성** → **스크립트 속성 추가**

| 속성 | 필수 | 값 |
|---|---|---|
| `TG_TOKEN` | ✅ | 3-1에서 받은 봇 토큰 |
| `GEMINI_API_KEY` | ✅ | 4에서 받은 API 키 |
| `SPREADSHEET_ID` | ✅ | 5-2의 스프레드시트 ID |
| `GEMINI_MODEL` | 선택 | 도연 모델 (기본 `gemini-3.8-flash`) |
| `GEMINI_FALLBACK_MODEL` | 선택 | 혼잡 시 보조 모델 (기본 `gemini-3.5-flash-lite`) |
| `REMIND_MINUTES` | 선택 | 일정 알림 시점(분, 5~180, 기본 60) — `/setup`에서 변경 |
| `MORNING_BRIEF_HOUR` / `EVENING_BRIEF_HOUR` / `COMPLETION_CHECK_HOUR` | 선택 | 아침·저녁 브리핑, 완료 확인 시각(0~23, 기본 7·17·19) — `/setup`에서 변경 |
| `AGENT_ENABLED` | 선택 | `on`이면 도비서 사용 (기본 꺼짐, 12장 참고) |
| `AGENT_MODEL` | 선택 | 도비서 모델 (기본 `gemini-3.8-flash`) |
| `ALLOWED_CHAT_IDS` | **강력 권장** | 봇을 쓸 수 있는 대화방 ID (6-10에서 자동 설정). 비어 있으면 누구나 봇을 쓸 수 있음 |

> 그 밖의 속성(`BRIEF_CHAT_ID`, `RELAY_SECRET`, `INBOX_…` 등)은 봇이 자동으로 만들고 관리합니다. **직접 지우지 마세요.**

> ⚠️ `-i` 없이 `clasp deploy`만 하면 **새 URL**이 생겨 Cloudflare 설정(`GAS_URL`)도 바꿔야 합니다.
> 편집기에서 할 때는 **배포 → 배포 관리 → ✏️ 연필 → 버전: 새 버전 → 배포**를 사용합니다. ("새 배포" 버튼 ❌)

### 6-9. 1분 트리거 만들기 (최초 1회)
편집기에서 `setupPolling` 실행
- 1분마다 `pollUpdates`가 실행되는 트리거가 생깁니다.
- 확인: 왼쪽 ⏰ **트리거** 메뉴에 `pollUpdates / 시간 기반 / 1분마다`
- ⚠️ `setupPolling`은 텔레그램 웹훅을 해제합니다. 중계를 이미 연결한 상태에서 트리거만 다시 만들었다면 **반드시 `connectRelay`를 다시 실행**하세요.

### 6-10. 대화방 등록·잠금
1. 텔레그램에서 봇에게 `/briefon` 전송 → 이 대화방이 브리핑·알림을 받는 방(`BRIEF_CHAT_ID`)으로 저장됨
2. 편집기에서 `lockBotToMyChat` 실행 → 이 대화방에서만 봇이 동작하도록 잠금 (`ALLOWED_CHAT_IDS` 자동 설정)
   - ⚠️ **꼭 실행하세요.** 잠그지 않으면 봇을 검색한 다른 사람도 일정을 보거나 `/briefon`으로 브리핑을 가져갈 수 있습니다.

## 7. Cloudflare Worker 중계 설정 (즉시 응답)

### 7-1. 왜 필요한가
Apps Script 웹앱은 응답할 때 302 리디렉션을 돌려주기 때문에, 텔레그램이 이를 실패로 보고 같은 메시지를 계속 다시 보냅니다. Cloudflare Worker가 텔레그램에 즉시 정상 응답을 주고 메시지를 Apps Script로 넘겨서 이 문제를 없애고, **1분 대기 없이 즉시 처리**되게 합니다.

### 7-2. 현재 설정값

| 항목 | 값 |
|---|---|
| workers.dev 하위 도메인 | `redcry.workers.dev` |
| Worker 이름 | `dobiseo-relay` |
| Worker 주소 | `https://dobiseo-relay.redcry.workers.dev` |
| 텔레그램 웹훅 주소 | `https://dobiseo-relay.redcry.workers.dev/telegram` |
| Worker 코드 | `E:\GAS\TeleBot\worker.js` |

> Worker 주소는 `Code.gs`의 `RELAY_URL` 상수와 같아야 합니다. 이름을 바꾸면 이 상수도 고치고 재배포하세요.

### 7-3. 1단계 — 비밀키 만들기 (Apps Script)
1. 편집기에서 `createRelaySecret` 실행
2. 실행 로그에 나온 **64자리 비밀키**를 복사 (다음 단계에서 사용)
   - ⚠️ 이 키는 채팅·문서에 남기지 마세요. 다시 필요하면 `createRelaySecret`을 다시 실행해 새로 만들고 7-5·7-6을 반복합니다.

### 7-4. 2단계 — Worker 만들기 (Cloudflare 대시보드)
1. https://dash.cloudflare.com 로그인
2. 왼쪽 메뉴 **컴퓨트 → Workers 및 Pages**
3. 파란색 **[애플리케이션 생성]** 클릭
4. **Hello World로 시작**(Start with Hello World) 선택
5. 이름: **`dobiseo-relay`** (정확히 입력) → **[배포]**
6. 배포 완료 화면에서 **[코드 편집]**
7. 편집기의 기존 코드를 모두 지우고 `worker.js` 내용을 붙여 넣기 → 오른쪽 위 **[배포]**

### 7-5. 3단계 — 변수·비밀 등록 (Cloudflare)
Worker 화면 → **설정**(Settings) → **변수 및 비밀**(Variables and Secrets) → **추가**

| 이름 | 유형 | 값 |
|---|---|---|
| `GAS_URL` | 텍스트(Text) | `https://script.google.com/macros/s/AKfycbxHCdyYtQ4ooACA3uY8Onh66MWky8VAJCmWV9sD10DkAIyJBrwHuNjjVpvketShgwA/exec` |
| `TG_SECRET` | **비밀(Secret)** | 7-3에서 복사한 비밀키 |

저장(배포) 후 브라우저에서 `https://dobiseo-relay.redcry.workers.dev` 를 열어 **`ok`** 가 보이면 정상입니다.

### 7-6. 4단계 — 텔레그램 연결 (Apps Script)
1. 편집기에서 `connectRelay` 실행
2. 로그에 **"✅ 중계 연결 완료"** 가 나오면 끝
3. 텔레그램에서 `/today` 전송 → 몇 초 안에 답이 오면 성공

### 7-7. 중계 상태 확인·해제
| 상황 | 실행할 함수 |
|---|---|
| 중계가 잘 되는지 확인 (`last_error_message` 확인) | `relayStatus` |
| 문제가 생겨 1분 폴링 방식으로 되돌리기 | `stopRelay` |
| 다시 중계로 연결 | `connectRelay` |

### 7-8. Worker 코드 (`worker.js`)
```javascript
export default {
  async fetch(request, env, ctx) {
    const url = new URL(request.url);
    if (request.method !== 'POST' || url.pathname !== '/telegram') {
      return new Response('ok', { status: 200 });
    }
    if (!env.TG_SECRET || request.headers.get('X-Telegram-Bot-Api-Secret-Token') !== env.TG_SECRET) {
      return new Response('forbidden', { status: 403 });
    }
    const body = await request.text();
    ctx.waitUntil(
      fetch(env.GAS_URL + '?key=' + encodeURIComponent(env.TG_SECRET), {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: body,
        redirect: 'manual'
      }).catch(err => console.log('GAS 전달 실패: ' + err))
    );
    return new Response('ok', { status: 200 });
  }
};
```

## 9. 사용 방법 — 도연

평소에는 **도연**과 대화하면 됩니다. 자연어로 편하게 말하면 Gemini가 해석합니다.
> 링크(URL)가 들어 있고 날짜·시간 표현이 없는 메시지는 일정이 아니라 **검토 목록**으로 들어갑니다(10-A).

### 9-1. 일정 등록
```
내일 오후 3시 운영위원회 등록해줘
10/21 저녁 6시 서구청-복지관장 저녁식사 (서구청)
12/22~24 종일 서구지회 선물전달
```
- 여러 일정을 **줄바꿈으로 한 번에** 보내도 각각 등록됩니다.
- `-`로 시작하는 줄은 바로 위 일정의 **메모**가 됩니다.
- 괄호 안 지명은 **장소**로 들어갑니다. 예: `(창원)`, `(Zoom)`
- 시간이 없으면 **종일 일정**, 종료 시간이 없으면 **1시간**으로 등록됩니다.

### 9-2. 일정 조회 (즉시 응답, Gemini 미사용)
```
오늘 일정 브리핑해줘
내일 일정
이번주 일정
다음 주 일정 뭐 있어?
이번달 일정
```

### 9-3. 일정 수정·삭제 (확인 버튼 방식)
```
보수교육 5시로 바꿔줘
회의 장소 본관 3층 추가
직원회의 1시간 늦춰줘
워크숍 삭제해줘
```
1. 도연이 **변경 전 → 변경 후**를 보여주고 **[✅ 수정] [취소]** 버튼을 보냅니다.
2. 같은 이름의 일정이 여러 개면 **번호 버튼**으로 어느 것인지 고릅니다.
3. 버튼을 눌러야 캘린더·시트에 반영됩니다. (24시간 지나면 만료)
- 대상 범위: 지난 7일 ~ 앞으로 60일 / 반복 일정은 제외

### 9-4. 중복·겹침 경고
- 같은 날 비슷한 제목(🔁)이나 시간이 겹치는 일정(⏱️)이 있으면 **등록을 보류**하고 **[✅ 그래도 등록] [취소]**를 묻습니다.
- 수정할 때 바뀐 시간에 다른 일정이 있으면 경고와 함께 **[✅ 그래도 수정]** 버튼이 나옵니다.

### 9-5. AI 서버가 혼잡할 때
- 봇이 자동으로 재시도합니다. 실패하면 **"⏳ 자동으로 다시 시도할게요"** 안내가 **한 번만** 오고, 1·2·4·8·15분 간격으로 약 30분간 재시도합니다.
- **같은 메시지를 다시 보낼 필요가 없습니다.** (다시 보내도 하나로 합쳐집니다)
- 완료되면 "✅ 앞서 보내신 '…'에 대한 답변입니다"로 알려줍니다.
- 명령어(`/today` 등)와 빠른 조회는 혼잡과 무관하게 즉시 동작합니다.

### 9-6. 빈 시간 찾기
도연에게 그냥 물어보면 캘린더를 확인해 빈 시간을 알려줍니다. (Gemini는 기간·소요시간 해석에 한 번만 쓰고, 계산은 코드가 직접 하므로 빠릅니다.)
```
다음 주에 2시간 비는 시간 찾아줘
목요일 오후에 1시간 돼?
이번 주에 회의 잡을 만한 시간 있어?
```
| 항목 | 기본값 | 바꾸는 법 |
|---|---|---|
| 기간 | 오늘부터 7일 | "다음 주", "10/20~10/24" 등 (최대 14일) |
| 소요시간 | 1시간 | "2시간", "30분" |
| 시간대 | 09:00~18:00 | "오전"(09~12), "오후"(13~18), "저녁"(18~21) |
| 주말 | 제외 | "주말 포함", "토요일" |

- 날짜별로 빈 시간대를 묶어서 보여주고, 빈 시간이 없는 날도 따로 알려줍니다.
- **종일 일정은 바쁜 시간으로 계산하지 않고** 그날 옆에 📌로 표시합니다. 출장·행사라면 직접 확인하세요.
- 등록은 하지 않습니다. 마음에 드는 시간이 있으면 "10/13 10시~12시 ○○ 회의 등록해줘"처럼 이어서 말하면 됩니다.

## 10-A. 사용 방법 — 검토 목록 (링크·자료 확인)

날짜·마감 없이 **"검토했다/안 했다"만 관리**하는 목록입니다. 시트의 `검토목록` 탭에 저장됩니다.

### 10-A-1. 추가하기 (Gemini 없이 즉시 처리)
| 보내는 메시지 | 결과 |
|---|---|
| `파일 다운 https://…` | 메모 "파일 다운" + 링크로 추가 |
| 링크만 보내기 | 링크만 추가 |
| `검토: 운영위 자료 보기` | 링크 없이 메모만 추가 |
| 여러 줄에 링크 여러 개 | 줄마다 한 건씩 (한 번에 최대 10건) |

- 링크와 함께 **날짜·시간 표현**(10/22, 내일, 오후 8시, ~까지 등)이 있으면 **일정·할 일로 처리**합니다. 이때 링크는 일정 메모에 들어갑니다.
- 날짜가 들어 있어도 검토로 넣고 싶으면 앞에 `검토:`를 붙이세요.
- 이미 검토 대기 중인 같은 링크는 다시 추가하지 않습니다.

### 10-A-2. 목록 보기·완료
- `/review` 또는 "검토 목록", "검토할 거 뭐 있어?" → 목록과 **[✅ 번호. 제목]** 버튼
- 버튼을 누르면 `완료`로 바뀌고, **[↩️ 방금 완료한 것 되돌리기]** 버튼이 함께 나옵니다.
- 아침 브리핑(기본 7시)에 "🔎 검토할 것 n건"이 표시됩니다.

### 10-A-3. 링크를 다루는 원칙 (보안)
- 봇은 링크를 **저장하고 보여주기만** 합니다. **링크를 열지 않고**, **Gemini에도 보내지 않습니다**. (일정 메시지 속 링크도 Gemini에는 `[링크1]`로 가려서 보내고, 결과에서 복원합니다.)
- 봇의 답장에는 **링크 미리보기를 붙이지 않습니다**. 텔레그램 서버가 링크에 접속하지 않게 하려는 것입니다.
- `fbclid`, `utm_…`, `gclid` 같은 **추적용 값은 지우고** 저장합니다. 페이지를 여는 데 필요한 값(예: Zoom 비밀번호 `pwd`)은 그대로 둡니다.
- `http://`·`https://` 주소만 링크로 저장합니다. `=`, `+`, `-`, `@`로 시작하는 글은 시트에서 수식으로 실행되지 않게 처리합니다. (검토목록 탭에 적용)
- 공유 토큰이 담긴 문서 링크는 시트와 텔레그램 대화에 남으니, 시트 공유 범위를 본인으로 유지하세요.

| **19:00** | 🌙 오늘 일정 완료 확인 [✅ 완료] [❌ 미완료] | `/checkon` · `/checkoff` |

### 11-2. 마감 D-day 알림
제목에 **회신·제출·마감·신청·접수·납부·보고서**가 들어간 캘린더 일정은 아침 브리핑에서 **D-3, D-1**에 미리 알려줍니다.

### 11-3. 저녁 완료 확인 (기본 19시)
1. 오늘 일정마다 **[✅ 완료] [❌ 미완료]** 버튼이 옵니다.
2. 누르면 메시지에 ✅/❌가 표시되고 시트 **H열 '완료여부'**에 기록됩니다.
3. 답하지 않은 일정은 "미확인"으로 남습니다.
- 지금 바로 확인: `/check`

### 11-4. 처리하지 않은 지난 일정 (다음 날 아침)
미완료·미확인 일정마다 4개의 버튼이 붙습니다.

| 버튼 | 동작 |
|---|---|
| **✅완료** | 완료로 기록 |
| **📝할일로** | 할 일 목록으로 옮김 (메모에 원래 날짜 기록) |
| **📅날짜변경** | "언제로 옮길까요?" → "금요일 오후 3시"처럼 답하면 변경 전/후 확인 버튼 → 반영 (취소: "취소") |
| **🗑무시** | 더 이상 묻지 않음 |

- 8일 이상 지난 미처리 일정은 묶어서 **[🗑 오래된 N건 모두 무시]**로 정리합니다.
- 언제든 `/pending`으로 다시 볼 수 있습니다.
- 완료 확인을 처음 시작한 날 이전 일정은 대상에서 제외됩니다.

### 11-5. 시각·알림 설정 바꾸기 (`/setup`)
텔레그램에서 `/setup`(또는 `/설정`)을 보내면 현재 설정과 버튼이 나옵니다. 코드 수정이나 재배포 없이 바로 바뀝니다.

| 버튼 | 고를 수 있는 값 | 기본값 |
|---|---|---|
| ☀️ 아침 브리핑 | 05~10시 | 07시 |
| 🌆 저녁 브리핑 | 15~21시 | 17시 |
| 🌙 완료 확인 | 17~22시 | 19시 |
| ⏰ 일정 알림 | 10·15·30·45분, 1시간, 1시간 30분, 2시간 전 | 1시간 전 |
| ✅/⛔ 브리핑·일정 알림·완료 확인 | 켜기·끄기 (켜면 이 대화방으로 받음) | 켜짐 |

- 값을 고르면 **다음 정시부터** 적용됩니다. 이미 오늘 받은 브리핑은 다시 오지 않습니다.
- **↩️ 기본값으로**를 누르면 코드의 기본값으로 돌아갑니다.
- 두 항목을 같은 시각으로 정해도 1분 간격으로 차례로 보내줍니다.
- 브리핑을 꺼도 완료 확인은 따로 동작합니다. (각각 켜기·끄기)
- 설정은 **등록된 대화방**(`ALLOWED_CHAT_IDS`, 없으면 브리핑 받는 대화방)에서만 바꿀 수 있습니다.
- 값은 스크립트 속성(`MORNING_BRIEF_HOUR` 등)에 저장됩니다. 편집기에서 직접 고쳐도 됩니다.

## 12. 사용 방법 — 도비서(AI 비서)

> ⏸️ **현재 꺼져 있습니다 (기본값).** 쓰임새에 비해 응답이 느려서 끄고, 가장 쓸모 있던 **빈 시간 찾기는 도연으로 옮겼습니다**(9-6).
> - 꺼져 있을 때 "도비서야 …"라고 보내면 호출어만 떼고 **도연이 처리**합니다. ("도비서야"만 보내면 쉬고 있다고 안내)
> - 다시 켜려면: 스크립트 속성에 `AGENT_ENABLED` = `on` 추가 (코드 수정·재배포 불필요). 끄려면 속성을 지우거나 `off`.
> - 아래 내용은 켰을 때의 사용법입니다.

### 12-1. 부르기·끝내기
| 동작 | 방법 |
|---|---|
| 부르기 | `도비서야`, `도비서, 내일 뭐 있어?`, `/비서` |
| 대화 이어가기 | 한 번 부르면 이후 메시지는 도비서가 처리 (답에 🧑‍💼 도비서 표시) |
| 끝내기 | `끝`, `종료`, `그만`, `도연` 또는 **10분 무응답** |

- "끝"을 보내면 **아직 답하지 못한 도비서 요청은 모두 취소**됩니다. (이미 반영된 일정은 그대로)
- 도비서와 대화 중에도 `/today` 같은 **명령어는 도연이 즉시 처리**합니다.

- `appsscript.json`의 권한(oauthScopes)을 바꾸면 편집기에서 함수를 한 번 실행해 **다시 승인**해야 합니다.

## 17. 문제 해결 (FAQ)

| 증상 | 원인·확인 | 해결 |
|---|---|---|
| 봇이 아무 답도 없음 | `relayStatus`의 `last_error_message` 확인 | Worker 주소 `ok` 확인 → `GAS_URL`·`TG_SECRET` 재확인 → `connectRelay` 재실행. 급하면 `stopRelay` |
| `forbidden`/403 오류 | Worker의 `TG_SECRET`과 스크립트 속성 `RELAY_SECRET` 불일치 | `createRelaySecret` → Worker `TG_SECRET` 교체 → `connectRelay` |
| 코드 고쳤는데 답장 내용이 그대로 | 배포를 안 함 | `clasp deploy -i …` 실행 |
| 브리핑·알림이 안 옴 | 트리거 없음 / 꺼짐 / 대화방 미등록 | ⏰ 트리거 확인, `/setup`에서 켜짐(✅) 확인 또는 `/briefon`·`/remindon`·`/checkon` |
| 브리핑 시각을 바꾸고 싶음 | — | `/setup` → 아침·저녁·완료 확인 버튼 (다음 정시부터 적용) |
| "⏳ AI 서버가 혼잡…" | Gemini 일시 혼잡 | 기다리면 자동 처리. 자주 발생하면 `GEMINI_MODEL` 변경 검토 |
| `Gemini API HTTP 404 … no longer available` | 모델 지원 종료 | `GEMINI_MODEL`/`AGENT_MODEL`을 최신 모델로 |
| `Gemini API HTTP 400/403` | API 키 오류 | AI Studio에서 키 확인 후 `GEMINI_API_KEY` 갱신 |
| "캘린더에 접근할 수 없습니다" | 캘린더 권한 없음 | 캘린더 공유 설정에서 운영 계정에 "변경 및 공유 관리" 권한 |
| 답장이 늦게·뒤섞여 옴 | 보관함 처리 지연 | `showInbox`로 확인. 막혀 있으면 `clearInbox` |
| "도비서는 지금 쉬고 있어요" | 도비서 꺼짐(기본) | 정상. 필요하면 `AGENT_ENABLED`=`on` (12장) |

| 링크가 들어간 일정이 검토 목록으로 감 | 날짜·시간 표현이 없음 | 날짜·시간을 함께 적거나, 일정이면 "10/22 8시 …"처럼 보내기 |
| 할 일 완료일(F열)이 비어 있음 | 시트에서 상태만 직접 바꿈 | 봇의 버튼·메시지로 완료하거나 F열에 직접 날짜 입력 |
| `clasp push`에 다른 `.gs`가 함께 올라감 | 폴더 안의 다른 `.gs` 파일 | `.claspignore`에 추가 후 다시 `clasp push` (6-4) |
| 시트에서 지웠는데 캘린더에 남음 | 동기화를 안 함 | `syncNow` 실행 (또는 `setupAutoSync`) |
| 시트 F열에 ⚠️ 표시 | 날짜 형식 오류 | 13-1의 형식대로 고친 뒤 `syncNow` |
| 같은 메시지가 반복 도착 (폴링 시절 증상) | 웹훅 302 문제 | 중계 연결 상태 확인 (`relayStatus`) |
